# Review of uploaded BattlespaceX ASP.NET controllers (2026-11-03)

## AuthController.cs (outside warzone repo)
- `AuthController : System.Web.Mvc.Controller` uses WebMatrix `WebSecurity.Login(email,password,persistCookie)`, `WebSecurity.Logout`, `Request.IsAuthenticated`, `User.Identity.Name`.
- `/api/auth/validate` looks up a user via `IUserManagement.GetUserByEmail`, rejecting deleted or inactive users.
- CRITICAL fail-open: if `DependencyResolver.Current.GetService<IUserManagement>()` returns null, Validate returns `isAuthenticated = true` without account checks. Login likewise skips active/deleted checks when service null. Fix separately before any token bridge.
- CORS only allows explicit origins, but CORS is not authentication or CSRF protection.
- Existing routes are configured in a separate `RouteConfig.cs` (not uploaded). The host application's identity database, deployment settings, and JWT configuration are not in the connected GitHub repo.
- No JWT/OIDC token bridge is currently implemented in this controller.

## CommentsController.cs (separate surface)
- `Edit(NewCommentViewModel Model)` calls `UpdateCommentMessage(Model)` with no visible authorization/ownership check in controller; need inspect underlying service before concluding exploitability.
- The requested Supabase RLS project should not silently change this separate feature.

## Chosen integration approach (requires deployment prerequisites)
- Preserve the current WebSecurity cookie login.
- Prefer a standards-based asymmetric OIDC JWT issuer/JWKS trusted by Supabase Third-Party Auth, with securely scoped stable UUID subject and `role=authenticated` claims.
- Token endpoint must authenticate existing cookie server-side, reject inactive/deleted user, authorize approved StratOps membership, send short-lived tokens only to allowlisted origin and protect against CSRF/session abuse. Revocation and refresh policy required.
- Supabase third-party auth requires OIDC issuer discovery URL, asymmetric JWT with `kid`. It is a separate Supabase configuration action and may have MAU costs.
- Without that issuer and configuration, no valid JWT can be generated by the current AuthController. **Do not merge or run target migration yet.**
- Staged policy schema uses a UUID `sub`, not necessarily a row in `auth.users`.
